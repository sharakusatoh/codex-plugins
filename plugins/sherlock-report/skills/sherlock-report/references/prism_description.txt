Prismとは：OpenAIが公開した科学論文の執筆と共同作業にGPT‑5.2を直接統合した（Overleafのような）LaTeXエディタ・ワークスペースです。Prismでは、プロジェクト数や共同作業者数に制限はありません。ChatGPTの個人アカウントをお持ちの方であれば無料で利用可能。下書き作成、改訂、共同作業、出版準備を、単一のクラウドベースかつ LaTeX ネイティブなワークスペースで行えます。GPT‑5.2 は、執筆プロセスの外側にある別ツールとして動作するのではなく、プロジェクトそのものの中で動作し、論文の構造、数式、参考文献、周辺の文脈にアクセスします。

Prismは、OpenAIが買収したクラウドベースのLaTeXプラットフォーム「Crixet」を基盤としており、それを統合製品として進化させたものです。これにより、成熟した執筆・共同作業環境を土台に、科学的なワークフローに自然に溶け込む形でAIを統合することができました。

URL：https://prism.openai.com/

※ChatGPTとは別ページで提供されている。

スターターガイド：
Prismは、OpenAIのフロンティアモデルを基盤とした共同作業型のLaTeXエディタで、文書の作成、編集、コンパイルを高速化します。ほとんどの問題は、Prismの組み込みインテリジェンスを使用してエディタ内で直接解決できます。

1. Prismの組み込みインテリジェンスを使用する
Prismには、OpenAIのフロンティアモデルを搭載したエディタネイティブのアシスタント機能が搭載されています。このアシスタントは文書のコンテキストを理解し、エディタを離れることなくLaTeXの生成、エラーの診断、修正案の提案などを行うことができます。ワークスペース下部のパネルからアクセスできます。

- LaTeX スニペットの生成: Prism に「4×4 表を作成する」や「キャプション付きの図を追加する」といった一般的な LaTeX 要素を作成させます。Prism はすぐに使用できる LaTeX を返し、保持と元に戻すオプションも提供するため、プロジェクトに直接挿入できます。

- コンパイルの問題を診断する：ドキュメントがコンパイルに失敗した場合は、パネルに問題の詳細を入力してください（例：「ドキュメントがコンパイルされません」）。Prism は問題解決のための質問をし、不足しているコマンドや未解決の参照など、考えられる原因を案内します。

- インラインでエラーを修正：エラーと警告は、エディターの余白に赤または黄色のマーカーで表示されます。Prismに特定のエラーの修正を指示すると、関連する行が分析され、問題点が説明され、適切な編集方法の提案が表示されます。提案を直接適用し、再コンパイルして修正を確認できます。

- 校正: Prism にセクションの校正を依頼し、エラーや論理のギャップがあれば強調表示してもらいます。また、セクションの明瞭性を向上させる方法についても提案してもらいます。

- 文献検索:見逃した可能性のある関連研究の提案を含め、論文に参考文献を追加します。

2. コンパイルエラーの診断
LaTeX ドキュメントがコンパイルされない場合は、次の手順を試してください。

- エラーマーカーを確認してください。Prismが問題を検出した箇所は、赤と黄色のマーカーで強調表示されます。マーカーをクリックして詳細を表示し、組み込みのアシスタントを使用してエラーを診断してください。

- コンパイルログを確認してください。コンパイルに失敗すると、PDFプレビューパネルにコンパイルログが表示されます。最初のエラーメッセージ（例えば、\end{document}が見つからないなど）に注目してください。後続のエラーは連鎖的な影響を及ぼしていることが多いためです。より正確なアドバイスを得るために、このメッセージをPrismと共有してください。

- 最近の変更を元に戻す:最近の編集後にエラーが発生した場合は、その変更を元に戻すか一時的にコメントアウトして、コンパイルが成功するかどうかを確認します。

- 最小限の例に絞り込む：問題が解決しない場合は、ドキュメントを必要不可欠な内容だけに簡素化します。関連のないセクションを削除すると、エラーの原因を特定しやすくなります。

3. 問題を回避するためのベストプラクティス
- ログインしたままにする:変更が保存され、セッション間で利用できるようになるために、常にログインしたまま作業します。

- サポートされているパッケージを使用する: Prism は、一般的に使用される多くの LaTeX パッケージをサポートしています。希少、古い、またはメンテナンスされていないパッケージは、予期しないコンパイルエラーを引き起こす可能性があります。

- 段階的に編集する：小さな変更を加えて頻繁にコンパイルします。これにより、どの編集でエラーが発生したかを特定しやすくなり、迅速に復旧できます。


その他のよくある質問：

1. アカウント、セキュリティ、請求
Q: 「ゼロデータ保持」（ZDR）は使用されていますか？お客様のデータを使ってトレーニングしますか？どのようなログ記録や保持が行われますか？
A: Prismは現在、「ゼロデータ保持」（ZDR）APIオプションを使用しておらず、製品改善のリクエストがあった後も一定期間ログを保持しています。ZDRは「お客様のデータをトレーニングに使用しない」こととは異なります。多くのAPIユーザーの場合、PrismはデフォルトでAPI提供データを使ってトレーニングを行いません。

Q: テキストが保存されず、人間による確認も行われないプライバシー モードや、EU のみのデータ保存場所は提供されていますか?
A: これらはリクエストされている機能であり、ロードマップ/バックログには記載されていますが、まだ確定したタイムラインはありません。

2. 共有とコラボレーション
Q: 「誰でも編集可能」リンクを共有できないのはなぜですか？（ドロップダウンでは「誰でも閲覧可能」しか選択
できません。）A: これは現状の仕様です。リンクベースの「誰でも編集可能」共有はまだサポートされていません。編集者は共同編集者として追加する必要があります（Prismアカウントが必要です）。

Q: 共同作業者が招待メールを受信して​​いません。どうすればプロジェクトにアクセスできますか?
A: 共同作業者にスパム/迷惑メールフォルダを確認してもらい、招待されたメールアドレスを使用してログインしてもらってください。最初のログイン後、共有プロジェクトが表示されるはずです。

3. プロジェクトのインポートとエクスポート
Q: ZIPファイルのアップロード/インポートが「プロジェクトのインポート中」で止まってしまいます。どうすればいいですか？
A: アップロードを再試行してください。再試行しても問題が解決しない場合は、ZIPファイルをサポートに共有して、インポートパスのデバッグを依頼してください。

Q: プロジェクトをZIP形式でエクスポート/ダウンロードするにはどうすればよいですか？
A: プロジェクト名をクリックし、「エクスポート」を選択すると、圧縮されたプロジェクトのコピーをダウンロードできます。エクスポートできるようになるまで、バックエンド接続が確立されるまで数秒かかる場合があります。

4. 信頼性、停止、接続性
Q: 更新後にプロジェクトが消えてしまいました。失われてしまったのでしょうか？
A: 再度更新してプロジェクトリストを再度確認すると、データが再び表示されるはずです。

Q: ページを更新したらプロジェクトが消えてしまいました。本当に消えたのでしょうか？
A: プロバイダの障害時に発生することがあります。もう一度お試しください。プロジェクトが再び表示されるはずです。表示されない場合は、サポートに復旧を依頼してください。

Q: サイトがオフラインのようです / アプリがバックエンドに接続できないと表示します。どうすればいいですか？
A: もう一度お試しください / リロードしてください。問題が解決しない場合は、調査いたしますので、表示されている内容の詳細（可能であればプロジェクトリンクも）をサポートまでお送りください。

5. データの整合性、回復、バックアップ、バージョン履歴
Q: ドキュメントがフリーズし、コンテンツが消え、コメントアンカーが先頭に移動しました。これはロールバックできますか？
A: まず.zip形式のバックアップをダウンロードしてください。コメントアンカーの位置は事後的に復元できない可能性があり、コメントは現在バックアップにエクスポートされていません。今後の問題発生を防ぐため、バージョン履歴機能の開発を進めています。コードフォーマッタを使用してフォーマットを修復してください。

Q: プロジェクトを再開したら、ファイルやコンテンツが元に戻ったり消えたりしました。何が起こったのでしょうか？
A: プロジェクトの保存を外部プロバイダーに依存していた時期がありましたが、利用急増時に対応が追いつかなかったため、接続エラーを減らし、再発を防ぐため、保存機能を社内システムに移行し、追加の安全対策を追加しました。

Q: コメントの位置は復元できますか？また、プロジェクトのバックアップにはコメントも含まれますか？
A: コメントの位置は事後的に復元できない場合があります。将来のインシデント発生時の復旧に備えて、定期的なバックアップ（例：約10分ごと）は実施していますが、コメントは現在ZIP形式のバックアップにはエクスポートされていません。

6. Zotero
Q: Zotero グループ ライブラリを Prism にインポートできないのはなぜですか?
A: Zotero グループ ライブラリはまだサポートされていません。個々のライブラリは機能しますが、グループ ライブラリは現在サポートされていません。

Q: Zotero との連携がうまくいかなくなってしまいました（例：アカウントや API キーを変更した後など）。どうすれば直りますか？
A: サポートでは、以前のユーザー/匿名ユーザーとの連携を解除するために、Zoteroの数値ID（ユーザー名ではありません）が必要となります。解除後、アカウントに再度連携させることができます。

7. Git
Q: Prism プロジェクトを Git (GitHub/GitLab) 経由で複製したり、所属機関の Git プラットフォームと同期させたりできますか?
A: Git 統合はまだ利用できませんが、今後の開発プロジェクトとして優先度が高くなっています。

8. LaTeXのビルドとトラブルシューティング
Q: クリーンなリビルド（Aux/toc/bblアーティファクトのクリア）を強制的に行うにはどうすればいいですか？
A: ページを再読み込みしてください。ページの更新により、クリーンなビルドが強制的に実行されます。

Q: 図や画像がPrismでは読み込まれませんが、他の場所では同じLaTeXが動作します。
A: インポートする.texファイルからの相対パスを使用してください。.texファイルがサブフォルダにあり、画像がプロジェクトルートにある場合は、パスの先頭に../を付けてください。

Q: コンパイルが非常に遅い、または完了しません。原因を特定するにはどうすればよいですか？
A: コンパイルが成功するまで、セクション（そしてそのセクション内の小さな部分）をコメントアウトし、問題の原因となっている行を絞り込んでください。また、ログの警告とエラーを最初から確認してください。

Q: 生成された.bblファイルで「Underfull/Overfull \hbox」という警告が表示されます。これはコンパイルエラーでしょうか？
A: いいえ、これはタイプセッティングに関する警告であり、致命的なコンパイルエラーではありません。PDF出力に問題がなければ、通常はこの警告を無視できます。

Q: Beamer では、フレーム内で lstlisting/listings 環境エラーが発生するのはなぜですか (例: 「Extra }」、または \endgroup を忘れた場合など)。
A: listing 環境を使用する場合は、Beamer フレームを [fragile] としてマークします。多くの場合、これらのエラーは解決されます。

Q: .bib ファイルが存在し、参考文献コマンドも指定しているにもかかわらず、\cite 引用が「[?]」と表示されます。有効な設定方法はありますか？
A: 有効な回避策の一つは、メイン文書から参考文献が正しく組み込まれていることを確認することです。BibTeX スタイルのワークフローの場合は、\bibliographystyle{plain} と \bibliography{refs} を含めます（refs.bib は実際のファイルです）。
